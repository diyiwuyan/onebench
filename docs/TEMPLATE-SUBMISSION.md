# OneBench 在线模板投稿

OneBench 的“模板”不是一种文件。投稿前先选择最小、最准确的类型：

| 类型 | 适合贡献什么 | 会改变用户什么 |
| --- | --- | --- |
| 职业包 `career-pack` | 大学生、教师、考研、运营等完整身份方案 | 主题、默认模块、首用示例 |
| 布局模板 `layout-template` | 晨间专注、项目冲刺、极简首页等排布 | 首页组件、顺序、尺寸 |
| 主题包 `theme-pack` | 色彩、字体、背景和插图氛围 | 只改外观，不碰内容 |
| 模块组合 `module-bundle` | 一组能共同完成任务的已有模块 | 添加所需模块 |
| 单模块 `module` | 一个独立、可复用的新能力 | 添加一个模块及其权限 |

## 在线投稿流程

1. 打开 GitHub 的“投稿一个模板或模块”表单；不会写代码也可以投稿创意。
2. 选择投稿类型，填写适合谁、解决什么问题、默认会出现哪些内容。
3. 逐个说明模块属于手动、自动计算、联网、连接器还是智能体能力，附桌面和手机截图。
4. 提交后机器人检查必填信息、截图、隐私确认和联网降级说明；通过后标记为“等待审核”。
5. 维护者检查重复性、安全与首用体验，再邀请作者或智能体生成 PR。
6. PR 通过自动校验和人工审阅后合并，条目进入公共注册表；用户联网检查后可看到更新。

Issue 是创意入口，不会让未知代码直接进入用户工作台。完整审核状态、版本规则和驳回条件见 [社区审核与版本流程](COMMUNITY-REVIEW.md)。

## 验收底线

- 第一次打开就能理解并使用。
- 所有示例条目可改、可删，不能把作者数据写死。
- 默认本地保存；联网能力必须声明来源和失败后的行为。
- 桌面、手机、离线 HTML、PWA 和浏览器新标签页保持同一套核心功能。
- 使用固定源码地址和版本审阅，不允许从注册表直接执行未经审查的第三方脚本。
