# 社区模板与模块目录

社区贡献的是可审阅、可组合、可追溯的配置和源码，不是从网页静默下载并执行的未知脚本。Demo 中的模块市场会先展示仓库内置快照；点“联网检查更新”只刷新目录元数据。

## 五类模板／模块贡献

| 类型 | 贡献内容 | 用户如何得到 |
| --- | --- | --- |
| 职业包 | 目标用户、主题、默认模块、首用示例 | 选择身份时一并装配 |
| 布局模板 | 首页组件、顺序、尺寸和侧栏分配 | 不覆盖用户内容，只重排工作台 |
| 主题包 | 色彩、字体、背景与插图 | 不改变模块和内容 |
| 模块组合 | 一组已登记模块的任务方案 | 一次添加所需模块 |
| 单模块 | 模块定义、真实 UI、本地数据结构 | 经审阅后随版本发布 |

需要外部服务的连接器属于高风险扩展，必须单独说明授权范围，不能默认上传。完整的在线投稿入口与验收要求见 [模板投稿说明](TEMPLATE-SUBMISSION.md)，维护者使用 [社区审核与版本流程](COMMUNITY-REVIEW.md) 完成分级审核。

## 模板贡献

提交模板包时，沿用 `packages/template-packs/template-pack.schema.json`，只引用已注册模块，并指定职业主题；在 PR 中说明目标人群、默认模块、示例内容、桌面和手机截图。运行：

```bash
npm run validate:templates
npm test
```

## 模块贡献

模块必须注册到 `packages/modules/core.manifest.json`，声明本地数据边界、所需权限和 UI 实现；需要在 `src/lib/local-data.js` 提供无隐私的真实示例状态，并在 `src/App.jsx` 复用当前设计系统。第三方连接器必须明确授权范围。不要上传用户任务、笔记、令牌或账号资料。

```bash
npm run validate:modules
```

## 公共目录与更新

`packages/community-registry/registry.json` 是机器可读的公共目录。每个条目固定来源仓库、文件路径与版本引用，并声明权限。更新本地目录：

```bash
npm run update:registry
```

该命令只下载和校验目录元数据，不会下载或执行第三方 JavaScript。真正使用社区模块时，应由智能体固定来源版本、审阅代码、合并到用户仓库、运行测试后再部署。这使“可更新”不以牺牲安全为代价。

## 审阅与发布流程

1. Fork 仓库并提交模板、模块或连接器。
2. 补全来源、固定 `ref`、权限、`requires` 与数据边界。
3. 运行模板、模块、目录、单元、构建和静态站点验证。
4. 在 PR 中附桌面与手机截图，并说明离线行为和联网行为。
5. 合并后更新公共目录快照；用户端看到更新提示，但不会静默执行代码。
6. 用户仓库由智能体拉取上游固定版本、展示差异、测试后再升级。

在线表单会自动检查必填内容并分配投稿类型；它只代表“信息完整”，不代表代码已经安全或被项目接受。所有模块源码、权限变化和迁移仍须经过 PR 与人工审阅。
